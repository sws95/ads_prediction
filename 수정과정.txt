문제 1 — Sample Selection Bias (SSB)
기존 CVR 예측 방식:

CVR 모델 = "클릭된 광고에서 전환이 일어날 확률"
학습 데이터 = 클릭된 샘플만 사용
추론 시점 = 모든 노출에 대해 CVR 예측해야 함

문제: 학습은 클릭 공간에서, 추론은 노출 공간에서. 분포가 다르다. 클릭 안 한 유저의 CVR을 예측하려는데, 모델은 그런 케이스를 본 적이 없음.
예시:

학습: 클릭한 유저 100명만 보고 "이 중 몇 명이 살까?" 예측 학습
추론: 광고 노출된 10,000명 전체에 대해 "이 사람이 살까?" 예측
학습 데이터의 100명은 이미 "클릭한 사람들"이라 편향됨

문제 2 — Data Sparsity
전환은 매우 드뭅니다.

노출 100만 건 중 클릭 1만 건 (CTR 1%)
클릭 1만 건 중 전환 100건 (CVR 1%)
전환 100건으로 CVR 모델 학습? 데이터 너무 적어서 학습 불안정

ESMM의 해결책
핵심 아이디어: CVR을 직접 학습하지 말고, CTR과 CTCVR을 동시에 학습하자. CVR은 그 사이에서 자연스럽게 유도된다.
수식:
pCTCVR = pCTR × pCVR

pCTR = P(클릭 | 노출) ← 학습 가능 (노출 데이터 많음)
pCTCVR = P(클릭∧전환 | 노출) ← 학습 가능 (노출 데이터에서 라벨 직접 계산)
pCVR = P(전환 | 클릭) ← 이게 우리가 원하는 값. 위 두 개로 유도.

2. 클래스 불균형으로 인한 pCTR 편향 (calibration)
CTR이 0.08%라 양성(클릭)이 극도로 희소합니다. 만약 negative downsampling이나 class_weight='balanced'를 쓰면 모델의 pCTR 출력이 실제 확률보다 부풀려집니다. 예를 들어 실제 0.08%인데 모델이 5%라고 출력하는 식입니다.
순위(ranking)만 보는 AUC는 이래도 괜찮지만, 입찰가 계산엔 치명적입니다. Linear의 bid = base × pCTR/avg_pCTR이나 ORTB의 sqrt(c/λ × pCTR + c²) - c 둘 다 pCTR의 절대값을 직접 씁니다. pCTR이 부풀려지면 입찰가도 왜곡됩니다. 그래서 제가 짠 코드에서 class_weight를 일부러 안 쓴 게 이 calibration 보존 때문입니다.
다만 downsampling을 쓰면 학습 속도가 빨라지는 장점이 있어서, 실무에선 downsampling 후 재보정(recalibration) 을 합니다. 공식은 p_corrected = p / (p + (1-p)/w) (w = downsampling 비율). 또는 Platt scaling, isotonic regression으로 보정합니다.


02_train_ctr.py를 negative downsampling + 재보정 + calibration plot 버전으로 다시 짜겠습니다.
핵심 공식부터 정리하면, negative만 비율 w로 downsampling하면(예: negative의 10%만 사용, w=0.1) 학습 데이터의 양성 비율이 인위적으로 부풀려집니다. 그래서 학습된 pCTR을 원래 분포로 되돌리는 보정이 필요합니다:
p_corrected = p / (p + (1 - p) / w)
w는 negative sampling rate입니다. 이 식은 Facebook의 CTR 논문(He et al. 2014)에 나오는 표준 보정식입니다.파일 생성됨, 명령 실행함, 파일 읽음파일 생성됨, 명령 실행함, 파일 읽음v2로 교체했습니다. 바뀐 점은 세 가지입니다.
negative downsampling을 학습셋에만 적용합니다. 양성(클릭)은 전부 유지하고 음성은 10%만 씁니다(NEG_SAMPLE_RATE = 0.1). 클릭이 워낙 희소해서 음성을 줄여도 양성 신호는 그대로 살아있고, 학습 데이터가 1/10 수준으로 줄어 LR 학습이 빨라집니다.
재보정은 recalibrate() 함수에서 p / (p + (1-p)/w) 식으로 합니다. downsampling 때문에 모델이 출력하는 raw pCTR은 실제보다 부풀려져 있는데, 이 식으로 원래 분포로 되돌립니다. 입찰 시뮬레이션에는 보정된 pCTR을 넘깁니다(sim_input의 pCTR 컬럼). raw도 pCTR_raw로 같이 저장해서 비교 가능합니다.
calibration plot은 calibration.png로 저장됩니다. 보정 전/후를 나란히 그려서, 가로축 예측 pCTR vs 세로축 실제 CTR이 대각선(perfect)에 얼마나 붙는지 보여줍니다. 보정 전은 점들이 대각선 아래로 처지고(과대예측), 보정 후는 대각선에 붙어야 정상입니다.
실행 후 확인 포인트는 출력의 세 줄입니다. avg pCTR (cal)이 실제 CTR과 비슷해지는지, logloss (cal)이 logloss (raw)보다 낮아지는지, 그리고 calibration.png에서 보정 후 점들이 대각선에 붙는지입니다. 이 세 개가 다 맞으면 보정이 제대로 된 겁니다.

오후 2:01
제 생각엔 파라미터 범위부터 넓히고, 그다음 시각화가 맞습니다. 순서가 중요합니다. 지금 Linear와 ORTB 둘 다 최적점이 탐색 범위 끝에 걸려 있어서(Linear는 base 60에서 최소값 쪽, ORTB는 lambda 5e-06에서 큰 값 쪽), 현재 숫자가 각 전략의 진짜 실력이 아닐 수 있습니다. 최적점을 제대로 잡기 전에 그래프를 그리면, 덜 튜닝된 결과를 그리게 됩니다. 그래서 범위 넓히기가 먼저입니다.

그리고 더 해볼 것도 꽤 있습니다. 가치 있는 순서대로 정리하겠습니다.

1순위: 파라미터 범위 넓히기 (필수)

Linear base를 40, 50까지 낮추고, ORTB lambda를 2e-05, 5e-05, 1e-04까지 키워서 각 전략의 최적점을 범위 안에 가두는 것. 이게 안 되면 비교가 불공정합니다. 반드시 해야 합니다.

2순위: 예산별 최적 파라미터 재탐색

지금은 full/8에서 찾은 파라미터를 모든 예산에 그대로 씁니다. 그런데 예산이 빡빡할 때와 넉넉할 때 최적 base/lambda가 다릅니다. 예산마다 파라미터를 다시 탐색해서 "각 예산에서 각 전략이 낼 수 있는 최선"으로 비교하면 훨씬 공정합니다. Constant도 지금 80 고정인데 예산별로 다시 잡아야 하고요.

3순위: 평가 지표 추가

지금은 획득 클릭 수만 봅니다. 여기에 두 개를 더하면 입찰 분석이 풍부해집니다. eCPC(클릭당 비용)는 이미 계산되니 표에 넣고, win rate(낙찰률)도 추가합니다. "ORTB가 클릭은 더 많이 따면서 eCPC는 더 낮다"는 식의 효율 스토리가 됩니다.

4순위: 시각화

위가 정리되면 예산(x축, 로그 스케일) vs 획득 클릭(y축)으로 세 전략 곡선을 그립니다. 빡빡한 구간에서 ORTB가 위, 넉넉한 구간에서 뒤집히는 게 한눈에 보입니다. Zhang 논문의 대표 그래프와 같은 형태라 포트폴리오에 강합니다.

그 이상 더 해볼 만한 것 (여력 되면)

bid landscape 모델링. 지금은 "내 입찰가 ≥ 시장가면 낙찰"로 단순화했는데, 실제 RTB는 시장가를 모르는 상태에서 입찰합니다. 그래서 win rate를 입찰가의 함수로 추정하는 win rate model(예: w(bid) = bid/(bid+c))을 만들고, 그걸 ORTB 유도에 넣는 게 논문의 정식 버전입니다. 이걸 하면 "교과서 ORTB를 제대로 구현했다"는 깊이가 생깁니다. 다만 난이도가 한 단계 올라갑니다.

또 하나는 KM(Kaplan-Meier) 기반 시장가 분포 추정인데, 이건 입찰에서 진 경우의 시장가를 censored data로 다루는 기법입니다. iPinYou 입찰 논문의 표준이지만 여기까지 가면 범위가 꽤 커집니다.

제 추천은 1~4순위까지 하고 마무리하는 겁니다. 그게 "CTR 예측 → 입찰 전략 → 예산 제약 평가"라는 완결된 스토리를 만들고, 각 전략을 공정하게 튜닝해서 비교한 단단한 결과가 됩니다. bid landscape 모델링(5순위)은 시간 여유가 있고 더 깊이 보여주고 싶을 때 추가하는 보너스고요.

1~3순위를 한 스크립트에 합쳐서 03을 업그레이드한 다음 4순위 시각화까지 한 번에 갈까요? 아니면 1순위만 빠르게 확인하고 단계적으로 갈까요?

왼쪽 (예산별 클릭)
예상한 패턴이 나옵니다. 빡빡한 구간부터 넉넉한 구간까지 Linear와 ORTB가 Constant를 일관되게 앞섭니다. 다만 예산마다 파라미터를 재탐색하니 Linear와 ORTB가 거의 겹칩니다. 이전(고정 파라미터)에선 빡빡한 구간에서 ORTB가 Linear를 약간 앞섰는데, 각자 최적 튜닝하니 둘 다 비슷한 상한에 도달한 겁니다. 이것도 정당한 결과입니다. "충분히 튜닝하면 Linear와 ORTB의 성능 차이는 작고, 둘 다 Constant 대비 우위가 명확하다"는 결론이고요. full/2(맨 오른쪽)에서 Constant만 208로 처지고 Linear·ORTB가 260으로 붙는 것도 일관됩니다.
가운데 (eCPC)
빡빡한 구간(왼쪽)에서 ORTB의 eCPC가 Linear보다 낮습니다. 클릭당 비용이 싸다는 거고, ORTB의 효율 우위가 여기서 드러납니다. 예산이 커질수록(오른쪽) 둘이 수렴하다가 full/2에서 역전됩니다. 이게 왼쪽 그래프의 클릭 수와 연결됩니다. 예산 빡빡할 땐 ORTB가 효율적으로 클릭을 모으고, 넉넉해지면 그 장점이 사라진다는 일관된 스토리입니다.
오른쪽 (bid landscape)
여기가 짚을 점이 있습니다. 모델(주황 선)이 경험적 점들(파랑)을 잘 못 따라갑니다. 저bid 구간(0~50)에선 모델이 위로 뜨고, 고bid 구간(80~)에선 경험적 점들이 0.9까지 빠르게 오르는데 모델은 0.8 근처에서 완만합니다. w(b)=b/(b+c0) 형태가 이 시장가 분포에 잘 안 맞는다는 뜻입니다.
이유는 시장가 분포 모양 때문입니다. b/(b+c0)는 완만하게 증가하는 곡선인데, 실제 1458 시장가는 특정 구간(50~80)에 몰려 있어서 그 구간에서 win rate가 급하게 오릅니다. 단순한 b/(b+c0) 한 개 파라미터로는 이 급경사를 표현 못 합니다.
이게 바로 앞서 말한 KM 추정이 필요한 지점입니다. b/(b+c0)라는 강한 가정 대신, 실제 시장가 분포를 데이터에서 직접 추정(KM)하면 경험적 점들에 훨씬 잘 맞습니다. 지금 그림은 "단순 win rate model의 한계"를 보여주는 거고, KM으로 가면 이게 개선됩니다.
그래서 다음 단계가 자연스럽게 정해집니다. 04로 KM 기반 시장가 분포 추정 + 그걸 쓰는 정식 ORTB를 만들면, 오른쪽 그래프의 적합이 좋아지고 ORTB가 시장가를 모르는 상태에서도 제대로 입찰하게 됩니다.
지금 결과도 그 자체로 완结된 스토리입니다. "단순 win rate model은 시장가 분포를 충분히 못 잡는다"는 한계를 그림으로 보여줬으니, KM이 왜 필요한지에 대한 동기까지 마련된 셈이고요.

04입니다. 두 가지를 합쳤습니다.
KM 추정(km_winrate)은 진 경매의 시장가를 censored로 다뤄서 win rate 곡선 W(b)=P(시장가≤b)를 비모수로 복원합니다. 진짜 RTB에선 진 경매의 시장가를 모르니, 학습 시점 입찰 정책이 50%만 이겼다고 가정하고 나머지를 censoring으로 부여해 KM을 시연합니다. censoring이 없으면 KM은 경험적 CDF와 같아지는데, 이 코드는 censoring을 줘서 KM이 censored data를 어떻게 보정하는지 보여줍니다.
정식 ORTB(find_lambda_for_budget)는 시장가를 모른다고 가정하고, KM win rate로 기대 비용을 계산해서 예산과 맞는 lambda를 이분탐색으로 찾습니다. 03처럼 실제 시장가를 보고 그리드 서치하는 게 아니라, 추정한 win rate만으로 lambda를 정하는 현실적인 정보 구조입니다.
비교는 두 축입니다. 왼쪽 그래프는 win rate model 세 개(경험적 CDF / KM / 03의 b/(b+c0))를 겹쳐서, KM이 단순 모델보다 실제 분포에 잘 맞는지 보여줍니다. 오른쪽은 KM 기반 정식 ORTB vs 오라클 그리드 ORTB의 예산별 클릭을 비교합니다.
해석 포인트를 미리 정리하면.
왼쪽에서 KM 곡선(점선)과 경험적 CDF(실선)가 b/(b+c0)(점점선)보다 서로 가까우면, "단순 파라메트릭 모델의 한계를 비모수 KM이 메운다"가 확인됩니다.
오른쪽에서 KM-ORTB가 오라클 그리드에 얼마나 근접하는지가 핵심입니다. 오라클은 실제 시장가를 보고 최적 lambda를 고른 "치트키"라 상한입니다. KM-ORTB가 시장가를 모르면서도 거기 근접하면, "정보 제약 하에서도 잘 작동한다"는 강한 결과입니다. 격차가 크면 KM 추정이나 lambda 탐색을 개선할 여지가 있다는 뜻이고요.
한 가지 미리 짚으면, expected_cost_and_win의 기대 비용을 sum(bid×winprob)로 단순화했습니다. 정확히는 이긴 경우의 조건부 기대 시장가 E[market|market≤bid]를 써야 하는데, KM에서 그걸 적분하는 건 복잡해서 근사했습니다. 그래서 KM-ORTB의 lambda가 약간 보수적으로/공격적으로 치우칠 수 있습니다. 결과 보고 클릭이 오라클 대비 많이 처지면 이 근사를 정밀화하겠습니다.

네, 이분탐색입니다. λ가 어떻게 결정되는지 단계별로 보겠습니다.
왜 이분탐색을 쓰나
λ는 "예산을 딱 맞게 쓰도록" 정하는 값입니다. 문제는 λ에서 예산으로 가는 식을 직접 못 푼다는 겁니다. λ를 정하면 → 모든 노출의 bid가 정해지고 → 그 bid로 입찰하면 얼마 쓸지(기대 비용)가 나오는데, 이 관계가 복잡해서 "예산 = X가 되는 λ"를 공식으로 못 구합니다. 그래서 λ를 이리저리 넣어보며 맞는 값을 찾아야 합니다.
단조성이 핵심
이분탐색이 가능한 건 λ와 비용 사이에 단조 관계가 있기 때문입니다.
λ 크다 → bid 전체적으로 낮음 → 적게 이김 → 비용 적게 씀
λ 작다 → bid 전체적으로 높음 → 많이 이김 → 비용 많이 씀
λ가 커지면 비용이 단조 감소합니다. 한 방향으로만 움직이니까, 이분탐색으로 "비용 = 예산"인 지점을 빠르게 좁힐 수 있습니다.
이분탐색 과정
04의 find_lambda_for_budget가 하는 일입니다.

매 단계마다 범위를 절반으로 줄입니다. 기대 비용이 예산보다 크면 "λ를 더 키워야 한다"(비용 낮추려고), 작으면 "λ를 줄여야 한다"(예산 더 쓰려고). 40번 반복하면 범위가 2^40분의 1로 좁혀져서 사실상 정확한 λ에 수렴합니다.
여기서 기대 비용을 어떻게 아나
이게 KM이 들어오는 지점입니다. 시장가를 모르는 상태에서 "이 λ로 입찰하면 얼마 쓸지"를 추정해야 하는데, 그걸 KM win rate로 계산합니다.
각 노출의 bid 계산 → KM win rate W(bid)로 "이길 확률" 추정
→ 기대 비용 = Σ (bid × 이길확률)
즉 실제 시장가를 보지 않고, KM으로 추정한 win rate만으로 "이 λ면 대략 이만큼 쓰겠다"를 계산해서 예산과 비교하는 겁니다. 이게 현실적인 정보 구조(시장가 모름)를 지키는 핵심이고요.
정리
λ 결정 = "예산을 다 쓰는 λ"를 이분탐색으로 찾기. 가능한 이유는 λ↑면 비용↓이라는 단조성. 각 λ의 비용은 KM win rate로 추정(시장가 모르니까). 40번 반복으로 수렴.
앞서 출력에서 예산별 λ가 빡빡(1/64) 3.8e-05 → 넉넉(1/2) 3.7e-06으로 단조 감소한 게 이 결과입니다. 예산이 많을수록 λ가 작아져서(bid 높여서) 더 공격적으로 입찰하는 거죠.
다만 앞서 말한 대로 지금 기대 비용을 Σ(bid×winprob)로 근사해서, 빡빡한 구간에서 λ가 약간 부정확합니다. 그게 KM-ORTB가 오라클보다 빡빡한 구간에서 더 처진 이유고요. 이 근사를 E[market|win] 기반으로 정밀화하면 개선됩니다.
censored 데이터(진 경매)는 사건으로 안 세지만, n_k(위험집합)에서는 빠집니다. 이렇게 절단된 관측의 정보를 부분적으로 반영합니다. 그래서 진 경매를 버리지도, 정확한 값으로 쓰지도 않고 "중간"으로 처리하는 거죠.
win rate는 W(b) = 1 - S(b) = "시장가가 b 이하일 확률" = "b로 입찰하면 이길 확률"입니다.
그럼 코드의 50%는 뭐냐
여기가 시연용 단순화입니다. 손승우님이 받은 iPinYou imp 로그는 iPinYou가 과거에 이긴 노출들이라, 사실 시장가가 다 관측돼 있습니다. 진 경매(censored) 데이터가 없어요. 그러면 KM이 그냥 경험적 CDF랑 똑같아져서, KM을 쓰는 의미가 안 보입니다.

왼쪽 그래프에서 KM(주황 점선)이 경험적 CDF(파랑 실선)보다 아래로 처진 게 그 효과입니다. 50%를 censored로 빼니까 win rate를 좀 보수적으로(낮게) 추정한 겁니다.
그래서 이게 맞는 방식이냐
시연으로는 맞는데, 현실 데이터로 제대로 하려면 두 가지 중 하나여야 합니다.
첫째, censoring을 무작위 50%로 인위적으로 주는 게 아니라, 실제 win/lose 라벨로 정의해야 합니다. iPinYou bid 로그(imp의 상위 집합, 입찰했지만 진 것도 포함)를 쓰면 진짜 censored 데이터가 생깁니다. 그러면 50% 같은 임의값 없이 데이터 자체의 win/lose로 KM을 돌립니다.
둘째, 지금처럼 시연만 할 거면 50%는 그냥 "censored가 이만큼 있다고 치자"는 데모 파라미터라고 명시하면 됩니다.
정리하면. KM은 "진 경매의 시장가를 모름(censored)"을 다뤄서 시장가 분포를 복원하는 생존분석 기법이고, 가격을 낮은 것부터 훑으며 생존확률을 곱해 win rate W(b)를 만듭니다. 코드의 50%는 imp 로그엔 censored가 없어서, KM 작동을 보여주려고 인위적으로 절반을 절단 처리한 시연용 값입니다. 제대로 하려면 bid 로그의 실제 win/lose로 censoring을 정의해야 합니다.
bid 로그를 써서 진짜 censored 데이터로 KM을 돌리는 버전으로 갈까요? 그러면 50% 가정 없이 실제 입찰 데이터의 win/lose로 win rate를 추정하게 됩니다. 다만 bid 로그가 imp보다 훨씬 커서(수백 MB bz2) 처리 시간이 늘어납니다.

단계별 계산
테스트셋 노출이 N개 있다고 하고, 노출 하나하나에 대해 계산해서 다 더합니다.
1단계: 각 노출의 입찰가 계산
주어진 λ로 모든 노출의 ORTB 입찰가를 구합니다.
pythonbids = sqrt(c/λ × pCTR + c²) - c
노출마다 pCTR이 다르니 입찰가도 다 다릅니다. 예를 들어 노출 3개면 [85, 50, 120] 이런 식.
2단계: 각 입찰가의 이길 확률 (KM)
각 입찰가로 이길 확률을 KM win rate 곡선에서 읽습니다.
pythonwprob = W(bids)   # KM 곡선에서 조회
예: bid 85 → W(85)=0.6, bid 50 → W(50)=0.3, bid 120 → W(120)=0.75.
3단계: 각 노출에서 이겼을 때 낼 돈 (여기가 핵심)
이게 앞서 손승우님이 짚었던 부분입니다. 이겼을 때 내는 건 입찰가(bid)가 아니라 시장가(2등가)고, 그건 항상 bid보다 작습니다(2nd price). 그래서 "이겼을 때 낼 평균 금액"을 KM 분포에서 계산합니다.
pythonE[market | market ≤ bid]   # bid 이하 구간의 평균 시장가
KM 곡선에서 "bid보다 싼 구간의 시장가 가중평균"을 구합니다. 예: bid 85로 이기면 실제론 평균 50쯤 낸다, 이런 값.
4단계: 노출별 기대비용 = 이길 확률 × 이겼을 때 낼 돈
python노출별 기대비용 = wprob × E[market|win]
예시:
노출1: bid 85,  W=0.6, E[market|win]=50 → 0.6 × 50 = 30
노출2: bid 50,  W=0.3, E[market|win]=28 → 0.3 × 28 = 8.4
노출3: bid 120, W=0.75,E[market|win]=70 → 0.75 × 70 = 52.5
각 노출에서 "평균적으로 이만큼 쓰겠다"는 기대값입니다. 이길 확률(못 이기면 0원)과 이겼을 때 낼 돈을 곱한 거죠.
5단계: 전부 더하면 총 기대비용
pythonexp_cost = Σ (wprob × E[market|win])
         = 30 + 8.4 + 52.5 + ... (모든 노출)
이게 "이 λ로 입찰하면 총 이만큼 쓸 것"이라는 추정치입니다.
이분탐색과 연결
이 exp_cost를 예산과 비교합니다.
exp_cost > budget → 너무 많이 쓴다 → λ 키워서 입찰가 낮춤 → 비용 ↓
exp_cost < budget → 예산 남는다 → λ 줄여서 입찰가 높임 → 비용 ↑
λ가 바뀌면 1단계의 입찰가가 바뀌고, 그게 2~5단계를 거쳐 exp_cost를 바꿉니다. 40번 반복하면 exp_cost ≈ budget인 λ로 수렴합니다.
중요한 점: 실제 시장가를 안 봄
이 전체 계산에서 실제 PayingPrice를 한 번도 안 씁니다. 오직 KM이 추정한 win rate W(b)와 거기서 나온 E[market|win]만 씁니다. 이게 "시장가를 모르는 현실적 상황"을 지키는 핵심입니다. 실제 시장가는 나중에 시뮬레이션에서 평가할 때만(이겼나 졌나 판정) 쓰고, λ를 정하는 단계에선 안 봅니다.
코드로 정리하면:
pythondef expected_cost(p, c, lam, km_곡선):
    bids = sqrt(c/lam × p + c²) - c        # 1단계
    wprob = KM_winrate(bids)                # 2단계
    cond_mean = E_market_given_win(bids)    # 3단계 (KM 분포에서)
    exp_cost = sum(wprob × cond_mean)       # 4~5단계
    return exp_cost
요약하면. 기대비용 = Σ (이길 확률 × 이겼을 때 낼 평균 시장가). 이길 확률은 KM win rate에서, 이겼을 때 낼 돈은 KM 분포의 조건부 평균에서 가져옵니다. 둘 다 KM 추정값이라 실제 시장가 없이 계산되고, 그래서 λ를 현실적으로 정할 수 있습니다.
